# Выделение через несколько блоков

Браузер не позволяет выделению выходить за пределы одного `contenteditable`-элемента. Поэтому
редактируемым элементом является не каждый блок, а **корень `<DocumentView>`**; блоки (`<Editable>`)
лежат внутри него и сами не редактируются. Выделение — обычное браузерное: мышь, `Shift+стрелки`,
`Ctrl/Cmd+A` (выделяет весь документ).

Ввод по-прежнему не меняет DOM напрямую: корень перехватывает `beforeinput`, превращает выделение в
координаты документа (`blockId` + смещение в тексте) и вызывает команды движка.

## Клик мимо текста

Клик в полосе слева от текста, правее конца строки, между блоками или вокруг документа ставит курсор на строку
на той же высоте: левее текста — в начало этой **визуальной** строки (у перенесённого абзаца — той строки, у
которой кликнули), правее — в её конец. Выше первого блока — первая строка, ниже последнего — конец последнего
блока. Протягивание мышью с полей выделяет текст, `Shift+клик` расширяет выделение. Кнопки, поля, ссылки,
меню и блоки без текста (картинка, разделитель) сохраняют своё поведение.

Внутри корня `<DocumentView>` это работает всегда. «Буферную зону» вокруг документа включает атрибут
`data-inkbrick-surface` на элементе-предке: тогда клик по любой обёртке редактора внутри этого элемента тоже
ставит курсор. Текст рядом с редактором (заголовок, подписи) обёрткой не считается и кликается как обычно.

```tsx
<main data-inkbrick-surface="">
  <div className="page">
    <DocumentView />
  </div>
</main>
```

## Что работает над выделением из нескольких блоков

| Действие                               | Команда движка                                                    |
| -------------------------------------- | ----------------------------------------------------------------- |
| Backspace / Delete / вырезание         | `deleteRange`                                                     |
| Ввод текста поверх выделения           | `deleteRange` + `replaceText` (один шаг undo)                     |
| Enter                                  | `deleteRange` + `splitBlock` (один шаг undo)                      |
| Вставка (в том числе многострочная)    | `deleteRange` + `replaceText`/`splitBlock`                        |
| Жирный / курсив / подчёркивание и т.д. | `toggleFormatRange` (снимает, если весь текст уже отформатирован) |

Правила `deleteRange`:

- Первый блок сохраняет свой тип и получает «хвост» последнего блока; блоки между ними удаляются.
- Дочерние блоки последнего блока переходят к первому (или встают после него, если схема не допускает вложенность).
- Контейнеры (`page`, `note`; в схеме `inline: false`) не могут быть границами выделения.
- Если внутри диапазона есть блок **неизвестного типа**, команда не выполняется — данные, смысл которых
  редактору неизвестен, не удаляются.
- Курсор после удаления ставится в точку склейки.

## Выделение как данные: `editor.selection`

Что выделено, движок знает сам, без интерфейса: `editor.selection` (`SelectionManager` из `@inkbrick/engine`).

```ts
type SelectionState =
  | { type: 'text'; anchor: BlockPoint; focus: BlockPoint } // каретка, если точки совпадают
  | { type: 'blocks'; ids: readonly string[] } // блоки целиком, в порядке документа
  | { type: 'cells'; tableId: string; anchor: TableCellRef; head: TableCellRef } // прямоугольник ячеек
  | null; // выделения нет

editor.selection.get(); // что выделено
editor.selection.range(); // { from, to } в порядке документа (для текста), какой бы край ни был подвижным
editor.selection.isCollapsed; // каретка
editor.selection.caret({ blockId, offset });
editor.selection.select(anchor, focus);
editor.selection.selectBlocks([id1, id2]);
editor.selection.selectCells(tableId, { row: 0, column: 0 }, { row: 1, column: 2 });
editor.selection.clear();

const stop = editor.selection.subscribe((selection, origin) => {
  // origin: 'api' | 'view' | 'command' | 'history' | 'document'
});
```

- **Откуда меняется.** `api` — код приложения; `view` — пользователь (интерфейс пишет сюда выделение текста с направлением,
  выбранные блоки и ячейки); `command` — команда вернула каретку (`dispatch`, `execute`), выделение встаёт туда; `history` —
  undo/redo; `document` — правка убрала то, на что указывало выделение.
- **Проверка.** Точка в несуществующем блоке отклоняется (`set` и его сокращения возвращают `false`), смещение за концом текста
  прижимается к концу. После каждой правки (своей, undo/redo, чужой) выделение проверяется снова: удалённые блоки выпадают,
  прямоугольник ячеек прижимается к таблице.
- **Интерфейс.** `@inkbrick/react` переносит на экран только выделение с источником `api` (каретку команд и undo он ставит
  сам). Так приложение может выделить найденное, восстановить выделение после перезагрузки или вести курсор из кода.
- **Без интерфейса** (сервер, тесты) модель работает так же: команды двигают каретку, undo возвращает её.

## Для разработчиков

- Свой блок с текстом — это компонент с `<Editable>`; он автоматически участвует в выделении.
- Блок-контейнер без текста помечайте в схеме `inline: false`.
- Нередактируемый виджет внутри блока (кнопка, маркер, картинка) помечайте `contentEditable={false}`.
- Команды можно вызвать и из кода: `editor.dispatch({ type: 'deleteRange', payload: { from, to } })`,
  `{ blockId, offset }` в любом порядке.

## Ограничения

- Копирование использует браузерное: в буфер попадает текст выделения; форматирование внутри редактора
  при вставке не переносится (вставляется простой текст).
- Перетаскивание выделенного текста (drag&drop) отключено.
