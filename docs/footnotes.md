# Сноски

Ссылка `[1]` в тексте и нумерованный текст сноски внизу заметки. Сноски не входят в набор по умолчанию: подключаются так же, как
оглавление и toggle, и в редактор, и в провайдер.

```tsx
import { footnoteBlocks } from '@inkbrick/react';

const editor = new Editor({ blocks: footnoteBlocks });

<EditorProvider editor={editor} blocks={footnoteBlocks}>
  <DocumentView />
</EditorProvider>;
```

## Как пользоваться

- **Вставить.** `/footnote` (или «Сноска») в любом текстовом блоке, в палитре команд — «Вставить: Сноска». На месте «/» появляется
  ссылка, в конце заметки — пустой блок сноски, каретка в нём: пишите текст. Одна правка в истории.
- **Переходы.** Клик по номеру в тексте ведёт к тексту сноски, кнопка «↩» у сноски — обратно, сразу за ссылкой.
- **Нумерация по порядку ссылок** в документе. Номера не хранятся, а считаются, поэтому вставка ссылки выше или удаление
  сдвигают номера сами. Текст новой сноски встаёт среди остальных по номеру. Ссылка на сноску из нескольких мест (скопированная
  внутри документа) имеет тот же номер.
- **Сноска без ссылки** (ссылку удалили) остаётся: вместо номера «?», кнопки возврата нет. Текст сноски не пропадает, пока его не
  удалят.
- Не вставляются в блок кода и в текст самой сноски.

## Модель

- Ссылка — символ-объект U+FFFC с атрибутом `footnote` (код сноски), как встроенная формула: удаление, склейка и перенос блоков
  работают как с любым символом, а смещения курсора совпадают с моделью. Номер рисуется в теневом корне (в `textContent` не
  входит).
- Текст — блок `block:footnote` с props `{ id }` (тот же код; `[\w-]{1,64}`), обычный текстовый блок в заметке. Схема в
  `footnoteBlocks`, `FootnoteSchema` в `@inkbrick/document`.
- Вставка из кода: `insertFootnote(editor, view, blockId, offset)` (одной правкой; каретку ставит сам), `createFootnote` — то же без
  каретки (для действий внутри чужой отрисовки). `getFootnoteIndex(editor)` — номера, места ссылок и текстов.
  `footnoteNumbers(blocks)` из `@inkbrick/document` считает номера по списку блоков.
- Команда `setInlineAttributes` принимает `footnote` только на символ-объект и только с допустимым кодом; вставка из буфера
  проверяет код так же.

## Экспорт

| Формат                     | Ссылка                              | Текст сноски                                    |
| -------------------------- | ----------------------------------- | ----------------------------------------------- |
| HTML                       | `<sup><a href="#fn-ID">N</a></sup>` | `<aside id="fn-ID" data-footnote="N">…</aside>` |
| Markdown                   | `[^N]`                              | `[^N]: текст` (отдельным блоком, как в GFM)     |
| Текст                      | `[N]`                               | `[N] текст`                                     |
| Буфер (в чужие приложения) | не передаётся                       | обычным абзацем                                 |

Внутри редактора ссылка при копировании и вставке сохраняется. Сноска без ссылки выводится с кодом вместо номера.

## Ограничения

- Вставка из Markdown (`[^1]`) не разбирается: разбор Markdown обратно в документ пока не реализован.
- Индекс читает модель документа, а не DOM, поэтому номера верны и для блоков вне окна виртуального рендерера. Он строится при
  первом показе сноски; после правки он смотрит только на изменённые блоки. Документ целиком обходится, лишь когда правка
  задела сноски или их порядок (новая или удалённая ссылка, перенос блока со сноской, смена кода сноски), и не чаще раза
  за такт. Обычный набор текста, в том числе в строке со сноской, на размер документа не завязан; документ без сносок
  ничего не платит.
- Если два блока сносок имеют один код (например, после копирования блока), главный первый в документе.
- Порядок блоков сносок внизу не пересортируется при правке: новая сноска встаёт на своё место, но если вы переставили ссылки местами,
  тексты остаются где были (номера слева при этом верные).
