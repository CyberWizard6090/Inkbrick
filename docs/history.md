# Undo / redo

История живёт в `@inkbrick/store` и работает поверх `Change.revert`: каждый шаг — набор изменений одной
транзакции. Горячие клавиши в блоках уже подключены: `Ctrl/Cmd+Z` — отменить, `Ctrl/Cmd+Shift+Z` и
`Ctrl+Y` — повторить (а также команды браузера «Отменить/Повторить»).

## API

```ts
editor.undo(); // { caret?: { blockId, offset } } | undefined — undefined, если отменять нечего
editor.redo();
editor.canUndo; // boolean
editor.canRedo;

editor.batch(() => {
  // несколько dispatch/execute — один шаг undo и один рендер; при ошибке откатывается всё
});

editor.sealHistory(); // следующая правка начнёт новый шаг
editor.clearHistory(); // забыть историю (например, после программного наполнения документа)

new Editor({ history: { limit: 200, mergeWindowMs: 1000 } });
```

В React для своих кнопок: `const { canUndo, canRedo, undo, redo } = useHistory();` — хук сам возвращает
курсор на место после отмены.

## Как формируются шаги

- Набор текста по одному символу в одном блоке в пределах `mergeWindowMs` — один шаг; то же для стирания
  (набор и стирание — разные шаги).
- Перемещение курсора (стрелки, Home/End, клик, потеря фокуса) — граница шага.
- Составные действия (вставка нескольких строк, Enter при выделении) выполняются через `editor.batch` и
  отменяются одним нажатием.
- После `undo` следующая правка не сливается с отменённым шагом; новая правка очищает стек redo.
- `store.transact(fn, { history: false })` — изменение без записи в историю.

## Ограничения

- История хранится в памяти и не сериализуется вместе с документом.
- Выделение (диапазон) не восстанавливается, только позиция курсора.
- IME-ввод попадает в историю после завершения композиции.
