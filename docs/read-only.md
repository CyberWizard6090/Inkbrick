# Режим только чтения и `selected`

## readOnly

```tsx
<EditorProvider editor={editor} readOnly>
  <DocumentView />
</EditorProvider>
```

или из кода: `editor.setReadOnly(true)` (подписка — `editor.subscribeReadOnly`, в React — `useReadOnly()`).

Режим защищает **документ**, а не только интерфейс:

- движок отклоняет **любые** команды (`dispatch`, `execute`, `batch`), а также `undo`/`redo`; `editor.can(...)` возвращает `false`;
- корень `<DocumentView>` перестаёт быть редактируемым (`contenteditable="false"`, `aria-readonly`), toolbar,
  ручки блоков, меню блока и slash-меню не показываются;
- выделение и копирование текста работают, в том числе через несколько блоков; ссылки открываются обычным кликом в новой вкладке;
- встроенные блоки отключают свои элементы управления (чекбокс to-do, выбор языка кода).

Prop `readOnly` у `EditorProvider` управляет режимом, пока задан; при размонтировании возвращается прежнее значение.
Чтение (`editor.formatsAt`, `editor.blocksBetween`, `serializeDocument`) в этом режиме доступно.

## Свойства блока: `selected` и `readOnly`

Компоненты блоков получают `BlockViewProps`:

```ts
{ block, editor, selected: boolean, readOnly: boolean }
```

- `selected` — блок затронут **непустым** выделением (в том числе выделением из нескольких блоков; одна каретка блок не «выделяет»).
  Подписка идёт на уровне блока: при смене выделения перерисовываются только те блоки, у которых флаг изменился.
- `readOnly` — редактор в режиме чтения: не показывайте редактирующие элементы (кнопки, поля, чекбоксы).

Встроенные блоки выставляют атрибут `data-selected="true"` на корневом элементе — за него можно зацепиться стилями.
