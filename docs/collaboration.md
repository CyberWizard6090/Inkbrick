# Совместная правка: патчи документа

Движок отдаёт свои правки и принимает чужие как **патчи** (функции `onPatch` и `applyPatch` из `@inkbrick/engine`: приложению без
совместной правки они не добавляют веса) — изменённые блоки целиком. На этом строится синхронизация через
сервер, сохранение изменений по частям и адаптеры к CRDT (Yjs, Automerge).

```ts
// Свои правки (и отмена, и повтор) — наружу.
import { applyPatch, onPatch } from '@inkbrick/engine';

const stop = onPatch(editor, (patch) => socket.send(JSON.stringify(patch)));

// Чужие — в документ.
socket.onmessage = (event) => applyPatch(editor, JSON.parse(event.data));
```

## Патч

```ts
interface DocumentPatch {
  blocks: Record<BlockId, BaseBlock | null>; // блок после правки; null — удалён
}

interface LocalPatch extends DocumentPatch {
  source: 'edit' | 'undo' | 'redo';
}
```

- В патче — все блоки, которые изменила правка, включая родителей, у которых поменялся список детей. Он самодостаточен: применить его
  можно к любой копии документа, где были эти блоки, а применить дважды — то же, что один раз.
- Патч — обычный JSON (без функций и классов): его можно хранить, пересылать и складывать в журнал.

## `applyPatch(editor, patch)`

- **Проверка.** Форма блоков, целостность дерева вокруг изменённых блоков (родитель числит блок, потомки существуют и указывают на
  него, корень не удаляется) и props по схеме. Не прошёл — `PatchError` со списком причин, документ не меняется.
- **Атомарно и вне локальной истории.** Патч применяется одной правкой с меткой `remote`: чужую правку нельзя отменить своим Ctrl+Z.
  Отмена возвращает блоки целиком, поэтому если чужой патч задел блоки из локальной истории, она очищается: иначе отмена затёрла бы
  чужую работу.
- **Без эха.** Правки с меткой `remote` не приходят в `onPatch`, поэтому их не нужно фильтровать при отправке.
- **Нормализация — своя правка.** После патча работают правила нормализации (`docs/schema-rules.md`) — отдельной правкой этого
  участника, без метки `remote`. Обычно она ничего не меняет (сервер прислал уже нормализованные блоки). Но если к патчу примешались
  свои ещё не отправленные правки (например, таблица стала «рваной»), то, что сделала нормализация, уходит в `onPatch` как своя
  правка — и на сервер. Блоки, которые создают правила, получают id от родителя и места, а не случайные: одна и та же нормализация
  у разных участников создаёт один и тот же блок.
- **Результат.** `applyPatch` возвращает то, что изменилось здесь, — блоки после применения и нормализации (`DocumentPatch`).
- **В режиме чтения** патчи применяются: зритель видит правки других.
- **Выделение** после чужой правки проверяется: удалённые блоки выпадают, смещения прижимаются к тексту (`docs/selection.md`).

## Одновременные правки

Автор патча не видел правок, которые пришли сюда раньше его патча, — а патч переписывает блоки целиком, в том числе списки детей.
`applyPatch` сводит такие правки по одним и тем же правилам у всех участников:

| Ситуация                                                                   | Что происходит                                                         |
| -------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Двое добавили блоки в одну заметку (каждый патч переписывает список детей) | Оба блока остаются: блок, о котором автор не знал, — за своим соседом  |
| Патч ссылается на ребёнка, которого здесь уже нет                          | Ссылка выпадает из списка                                              |
| Патч переносит блок, который здесь уже переехал в другое место             | Блок уходит из списка здешнего родителя: он ровно в одном месте        |
| Блок удалили, а в нём одновременно что-то добавили                         | Удаляется вместе с добавленным                                         |
| Блок сменил тип на тот, где детям не место (переключатель стал абзацем)    | Новые дети переезжают к деду, сразу за блоком                          |
| В таблице одновременно добавили столбец и строку, удалили последние строки | Нормализация дополняет строки ячейками, пустая таблица получает строку |

## Сервер

Чтобы все пришли к одному документу, правкам нужен один порядок. Его задаёт сервер — у него своя копия документа (`Editor` без
интерфейса):

```ts
const server = new Editor({ features }); // те же возможности, что у участников

socket.on('patch', (patch, from) => {
  try {
    const result = applyPatch(server, patch);

    // Всем, и автору тоже: результат — блоки после применения на сервере.
    broadcast(result);
  } catch (error) {
    if (!(error instanceof PatchError)) throw error;
    // Патч не подошёл: автор возвращается к документу сервера (снимок целиком).
    from.send({ snapshot: server.document.dump() });
  }
});
```

- **Рассылайте результат, а не исходный патч.** Сервер мог свести патч с чужими правками и нормализовать: участники должны получить
  то, что получилось у него.
- **Автору — тоже.** Его правка у него уже есть, но результат сервера может отличаться (слияние, нормализация).
- **Если участник не может применить патч сервера** (`PatchError`), он просит снимок и приводит документ к нему: патч со всеми
  блоками снимка и `null` для своих блоков, которых в снимке нет.

Так устроен тест `packages/engine/__tests__/concurrent-fuzz.test.ts`: три участника и сервер, случайные правки (текст, блоки,
перенос, вложенность, колонки, строки, столбцы и объединение ячеек таблиц), сообщения доставляются со случайными задержками. Когда
всё доставлено, документы всех участников совпадают с серверным и целы.

## Что патчи решают и что нет

Единица изменения — блок: последний записавший блок выигрывает. Этого достаточно, когда:

- редактирует один человек, а другие смотрят (трансляция, предпросмотр, вторая вкладка);
- правки идут через сервер, который задаёт им порядок (выше);
- участники правят разные блоки — в том числе добавляют блоки в одну заметку.

Одновременная правка **текста одного блока** двумя людьми (оба печатают в одном абзаце) так не сливается: победит один из них.
Для этого нужно посимвольное слияние — CRDT или OT. Патчи (`onPatch`, `applyPatch`) для него — точка подключения: адаптер переводит
патчи в операции своей модели и обратно.

## Хранилище

Низкий уровень — `editor.store.subscribeChanges((blockIds, info) => …)`: `info.source` — правка, отмена или повтор, `info.origin` —
метка правки (`TransactOptions.origin`, у чужих — `remote`).
