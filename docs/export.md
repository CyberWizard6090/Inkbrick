# Экспорт документа

Адаптеры работают поверх `Document` из `@inkbrick/document` и не зависят от React и DOM — их можно вызывать
на сервере и в сборочных скриптах.

```ts
import { toMarkdown, toHtml, toPlainText, exportDocument } from '@inkbrick/document';

toMarkdown(editor.document, { schema: editor.schema });
toHtml(editor.document);
toPlainText(editor.document, { title: false });
exportDocument(editor.document, 'markdown'); // 'text' | 'markdown' | 'html'
```

## Параметры

| Параметр | По умолчанию | Назначение                                                                                                   |
| -------- | ------------ | ------------------------------------------------------------------------------------------------------------ |
| `schema` | —            | Реестр схем: контейнерами считаются блоки с ролью `root`/`hub` (в том числе свои). Без него — `page`, `note` |
| `from`   | корень       | Экспортировать поддерево этого блока                                                                         |
| `title`  | `true`       | Первой строкой вывести заголовок страницы (`props.title`); только при экспорте всего документа               |

## Как блоки выглядят в каждом формате

| Блок                | Markdown                                                   | HTML                                                                    | Текст                                |
| ------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------ |
| paragraph           | абзац                                                      | `<p>` (+ `text-align`)                                                  | абзац                                |
| heading             | `#`…`######`                                               | `<h1>`…`<h6>`                                                           | строка                               |
| list bullet/ordered | `- ` / `1. `, вложенность — отступом                       | `<ul>` / `<ol>`, вложенные внутри `<li>`                                | `- ` / `1. `, отступ 2               |
| list todo           | `- [ ]` / `- [x]`                                          | `<input type="checkbox" disabled>`                                      | `[ ]` / `[x]`                        |
| quote               | `> `                                                       | `<blockquote>`                                                          | строка                               |
| callout             | `> [!NOTE]` (по тону: NOTE/WARNING/TIP/CAUTION)            | `<aside data-callout="тон">`                                            | строка                               |
| code                | ограждение из обратных кавычек с языком                    | `<pre><code class="language-…">`                                        | как есть                             |
| divider             | `---`                                                      | `<hr>`                                                                  | `---`                                |
| image               | `![alt](src)` + подпись курсивом                           | `<figure><img><figcaption>`                                             | подпись или alt                      |
| formula             | `$$` … `$$`; встроенная — `$код$`                          | `<div class="math display">`, встроенная — `<span class="math inline">` | исходный LaTeX                       |
| table               | таблица GFM (`\| a \| b \|`)                               | `<table>`, `<thead>`, `<colgroup>`, `text-align` в ячейках              | строки, ячейки через табуляцию       |
| toggle              | `<details>` (`open`, если раскрыт) с `<summary>`           | `<details>`, `<summary>`                                                | строка, вложенные блоки — с отступом |
| toc                 | список заголовков документа (`- `, вложенность — отступом) | `<nav>` со списком                                                      | список заголовков                    |
| columns             | содержимое колонок подряд, слева направо                   | содержимое колонок подряд                                               | содержимое колонок подряд            |
| footnote            | ссылка `[^1]`, текст — `[^1]: …`                           | ссылка `<sup><a href="#fn-…">1</a></sup>`, текст — `<aside id="fn-…">`  | ссылка `[1]`, текст — `[1] …`        |

Номер сноски считается по порядку ссылок, как в редакторе; у сноски без ссылки вместо номера её код.

Инлайн-форматирование: жирный, курсив, зачёркнутый, код, ссылка. Подчёркивание в Markdown выводится тегом `<u>`;
цвета отбрасываются. Фон блока попадает только в HTML (`background-color` в `style`, оттенок светлой темы), в Markdown и
тексте его нет. Блоки неизвестных типов выводятся как текст.

## Импорт из Markdown

`fromMarkdown` — обратное действие к `toMarkdown`: превращает текст Markdown в `Document`. Он лежит в отдельной точке входа
`@inkbrick/document/markdown`, поэтому в основной бандл пакета не входит (приложение, которому импорт не нужен, ничего не
платит за него).

```ts
import { createSchemaRegistry, serializeDocument, tableBlockSchemas } from '@inkbrick/document';
import { fromMarkdown } from '@inkbrick/document/markdown';

const schema = createSchemaRegistry(tableBlockSchemas);
const document = fromMarkdown(text, { schema, titleFromHeading: true });
const snapshot = serializeDocument(document, schema);
```

| Параметр           | По умолчанию | Назначение                                                                                              |
| ------------------ | ------------ | ------------------------------------------------------------------------------------------------------- |
| `schema`           | —            | Реестр схем (обязателен). Блока нет в реестре — его разметка остаётся обычным абзацем                   |
| `title`            | пусто        | Заголовок страницы (`props.title`)                                                                      |
| `titleFromHeading` | `false`      | Первая строка `# …` становится заголовком страницы, как её выводит `toMarkdown`; блоком она не остаётся |
| `rootId`           | `page-001`   | Идентификатор корневого блока                                                                           |
| `maxLength`        | `1 000 000`  | Наибольшая длина текста в символах; длиннее — `RangeError`                                              |
| `maxBlocks`        | `20 000`     | Наибольшее число блоков (строки и ячейки таблицы тоже блоки); больше — `RangeError`                     |

Разбираются те блоки, которые умеет выводить экспорт, и обратно без потерь: абзацы, заголовки `#`…`######`, списки
(`-`/`*`/`+`, `1.`/`1)`, `- [ ]`/`- [x]`, вложенность отступом), цитаты, `> [!NOTE]` (`NOTE`, `WARNING`, `TIP`, `CAUTION`),
ограждённый код с языком (три и более `` ` `` или `~`), `---`, картинки `![alt](src)`, таблицы GFM с выравниванием, формулы
`$$…$$` и `$…$` (также `\(…\)`), сноски `[^1]` и `[^1]: …`, `<details>` с `<summary>` как переключатель; в тексте — `**`, `*`,
`~~`, `` ` ``, `[текст](адрес)` и `<u>`. Для документа из `toMarkdown` круговой обход `fromMarkdown(toMarkdown(doc))` даёт
эквивалентный документ: тот же состав блоков, props и текст с форматированием (проверяется тестами на каждый блок и на смесь).

Что не возвращается и что стоит знать:

- Оглавление (`toc`) и колонки экспортируются как список и содержимое колонок подряд — в документ они не вернутся.
- Подпись картинки и кода (`*подпись*`) узнаётся по абзацу из одной строки в курсиве сразу после блока (через пустую
  строку): такой абзац после картинки или кода становится подписью.
- Номер сноски становится её кодом (`[^1]` → `id: '1'`). Заголовок страницы `# …` без `titleFromHeading` остаётся
  заголовком первого уровня. Таблица с пустой первой строкой — это таблица без заголовка (`header: false`).
- Блок, который родитель не принимает по схеме (код или цитата в переключателе, любой блок, кроме списка и абзаца, в
  пункте списка), ставится сразу после родителя. У пункта списка вложенными блоками считаются строки с отступом от трёх
  пробелов; строка с меньшим отступом — продолжение текста пункта.
- Картинка в середине абзаца остаётся текстом (`!` и ссылка); адрес ссылки с пробелами не принимается; титул
  `[a](url "title")` отбрасывается. Не поддерживаются заголовки подчёркиванием (`===`), код отступом, определения ссылок
  `[id]: url`, `&amp;` и прочие сущности — всё это остаётся текстом как написано.

Безопасность и пределы:

- HTML не выполняется и не вставляется: любой тег, кроме `<u>`, `<br>` и обрамления `<details>`/`<summary>`, остаётся
  обычным текстом (`<script>` — это строка «`<script>`», а не элемент).
- Ссылки пропускаются через `normalizeLinkUrl`/`isSafeUrl` (`javascript:`, `data:` и т. п. остаются текстом разметки),
  картинки — через `isSafeImageUrl`; значение, не прошедшее схему (например, `alt` длиннее 1000 символов), тоже остаётся
  текстом. Символ-объект U+FFFC в тексте заменяется на U+FFFD, чтобы нельзя было подделать формулу или сноску.
- Вложенность не превышает `MAX_NESTING_DEPTH`: что глубже, остаётся текстом абзаца рядом, ничего не пропадает.
- Размер ограничен (`maxLength`, `maxBlocks`); время разбора не растёт квадратично ни от текста, ни от вложенности:
  патологический ввод в сотни тысяч символов (тысячи `[`, `*`, `<details>`) обрабатывается за секунды.

## Безопасность

- Весь текст и значения атрибутов экранируются (HTML) или маскируются (Markdown: `\ * _ [ ] < > ~ |`, символы в начале строки,
  ограждение кода длиннее любой серии кавычек внутри).
- Ссылки пропускаются через `isSafeUrl`, картинки — через `isSafeImageUrl`; небезопасные (`javascript:`, `data:` не-картинки, SVG)
  выводятся только текстом.
- В HTML допустимы только значения `text-align` и тон callout из белых списков.
